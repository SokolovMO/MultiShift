# Самостоятельный выпуск MultiShift

Публичный адрес: https://sokolovmo.ru/multishift/ (Vyrex).
Apple Developer, нотарификация, GitHub App, Vercel и панель управления не нужны.
Приложение подписывается ad-hoc; архив и лента обновлений подписываются постоянным
ключом Ed25519. Sparkle показывает нативное окно и ждёт завершения операций перед
перезапуском. Установка обновления требует подтверждения.

## Выпуск

1. Увеличить `macos/build-number.txt` для каждой новой сборки; версию менять в
   `dragshift/__init__.py`. Никогда не заменять опубликованный ZIP тем же build.
2. Прогнать Python/Swift проверки; проверить Finder и конвертацию файлов.
3. На Mac с Apple Silicon и Python 3.12:

   ```sh
   bash scripts/prepare_sparkle.sh
   bash scripts/prepare_dmg.sh
   .venv/bin/python scripts/build_release.py --output /tmp/multishift-release-build-N
   ```

   Скрипт собирает приложение с обновлениями, проверяет ZIP после распаковки,
   подписывает архив и appcast и проверяет обе подписи. Включает соответствующие
   текущей сборке исходники, лицензии, установщик и страницу загрузки.
4. Опубликовать подготовленную папку:

   ```sh
   .venv/bin/python scripts/publish_release.py /tmp/multishift-release-build-N
   ```

   Скрипт проверяет подписи и хеши, загружает в отдельную папку на Vyrex, сохраняет
   предыдущие архивы и атомарно переключает `current`. Конфиг nginx при повторном
   выпуске не меняется. Скрипт не создаёт и не перезапускает proxy.
5. Скачать публичный ZIP, сверить SHA256 и подпись appcast; проверить первый запуск
   и реальное обновление предыдущей версии. Успешная сборка не заменяет этот шаг.

Ключ: `~/Library/Application Support/MultiReleases/Signing/MultiShift.seed`.
Он уже существует и переиспользуется. Не публиковать, не менять при каждом релизе;
сохранить зашифрованную резервную копию. Путь можно переопределить `--seed`.
Приватный ключ не входит в приложение, папку публикации или архив исходников.
`--url` позволяет перенести раздачу на другой HTTPS-сервер; старую ленту нужно
сохранять доступной для уже установленных версий.

## Первый запуск

ZIP можно открыть вручную через разрешение в настройках безопасности macOS.
Опубликованный `install.sh` устанавливает в `/Applications/MultiShift.app`, проверяет
HTTPS-загрузку, размер, SHA256, структуру архива, bundle ID, build, ключ обновлений,
подпись кода и selftest. Только после этого снимает карантин с этого приложения.
Это не нотарификация и не подтверждение личности разработчика Apple.
Первоначальное доверие — к HTTPS-сайту/скрипту; SHA256 из того же сайта не является
независимой подписью издателя. Последующие обновления Sparkle требуют Ed25519.
Установщик не использует sudo, не трогает оригиналы файлов и настройки, не убивает
активную конвертацию и сохраняет старое приложение для ручного возврата.

## Хостинг и возврат

Существующий nginx Vyrex обслуживает `/multishift/` из
`/var/www/multishift/current/`. Каждая публикация хранится отдельно в
`/var/www/multishift/releases/`. `previous` указывает на прошлую публикацию.
Для возврата атомарно направить `current` на `previous`; nginx reload не нужен.
Клиентам с уже установленной новой версией автоматическое понижение не предлагается:
исправление выпускается с большим build. Старые ZIP доступны для ручного возврата.

Сборка сейчас только для Apple Silicon, macOS 14+. Intel не заявлен.
Общие проекты `release-infra` и `multi-release-console` не используются MultiShift,
но оставлены на диске, поскольку обслуживают также MultiSwitcher.

## DMG для первой установки

Основная загрузка с сайта — оформленный DMG с иконкой приложения и ссылкой на
/Applications. Пользователь перетаскивает приложение в «Программы»; при наличии
старой копии Finder предлагает замену. Сам DMG ничего не устанавливает и не
запускает автоматически. ZIP остаётся архивом обновлений Sparkle и запасной загрузкой.
Сборщик создаёт DMG, проверяет его монтирование, подпись вложенного приложения и
selftest, затем отдельно подписывает DMG ключом Ed25519. SHA256 и подпись проверяются
перед публикацией. requirements-release.lock фиксирует только инструменты упаковки;
эти Python-пакеты не попадают в приложение.

## Homebrew

Официальный tap: https://github.com/SokolovMO/homebrew-apps .

```sh
brew tap SokolovMO/apps
HOMEBREW_MULTI_APPS_ALLOW_UNNOTARIZED=1 brew install --cask SokolovMO/apps/multishift
```

Явный параметр разрешает проверку подписи и снятие карантина только с MultiShift.
Без параметра сохраняется стандартная проверка Homebrew/macOS. В Homebrew 7 старого
`--no-quarantine` больше нет. SHA256 закреплён в публичном Git tap; это не нотарификация.
Для существующей побайтово совпадающей копии добавить `--adopt`, без `--force`.
Обновления с нативным окном — через «Проверить обновления» в приложении.
Альтернатива после завершения операций и выхода из приложения:

```sh
brew update
HOMEBREW_MULTI_APPS_ALLOW_UNNOTARIZED=1 brew upgrade --cask SokolovMO/apps/multishift
```

После каждого публичного build обновить tap командой `python3 scripts/update_casks.py`
из репозитория homebrew-apps, проверить diff и опубликовать cask. Обычный выпуск
приложения сам по себе не обновляет tap. `auto_updates true` оставляет плановые
обновления Sparkle; явно названный cask обновляется и через Homebrew.
